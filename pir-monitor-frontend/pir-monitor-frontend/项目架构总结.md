# PIR-Monitor-Frontend 项目架构总结

## 技术栈及职责

| 技术 | 在本项目中负责什么 |
|---|---|
| **Vue 3** | 页面组件、响应式数据绑定、组合式 API（ref/watch/onMounted） |
| **TypeScript** | 类型安全 — 定义 Device、MqttReport 等接口，编译期捕获类型错误 |
| **Vite 8** | 开发服务器 + 构建，配置 HTTPS 证书和 /api → 后端的代理转发 |
| **Pinia** | 全局状态管理 — 登录信息（auth）、设备列表（device）、告警（alarm）、聊天记录（chat）、MQTT 连接（mqtt） |
| **Vue Router 4** | 前端路由 — 按角色分三套布局（居民/保安/管理员），导航守卫控制页面访问 |
| **Axios** | HTTP 请求 — 封装 baseURL、自动带 token、统一处理错误码和 401 跳转 |
| **Element Plus** | UI 组件 — 表格、表单、弹窗、菜单、标签页、按钮、通知、时间线、分页等所有界面元素 |
| **ECharts** | 图表 — 活动记录的柱状图/饼图、保安总览的 7 日告警趋势折线图 |
| **MQTT.js** | 浏览器 WebSocket MQTT 客户端 — 订阅设备上报（人体感应/心跳）、发布布防指令到硬件 |

## 项目结构

```
src/
├── api/          # 8 个模块：auth, device, alarm, face, chat, camera, activity, statistics
├── stores/       # 5 个 Pinia store：auth, device, alarm, chat, mqtt
├── router/       # 路由（按角色分布局）+ 导航守卫
├── types/        # 全部 TS 类型定义
├── composables/  # useMqtt（页面挂载MQTT连接）、useFaceCapture（自动人脸抓拍）
├── layouts/      # ResidentLayout, GuardLayout, AdminLayout（三套侧边栏菜单）
├── views/        # 按角色分目录：login(2), resident(6), guard(3), admin(2), common(2)
└── components/   # 共享组件：MqttStatus, NotificationBell, FaceCapturePanel, CameraPlayer
```

## 关键数据流

### 布防切换
用户点开关 → toggleDefense() 乐观更新 statusMap → HTTP API + MQTT 命令双下发

### 实时更新
MQTT 上报 → mqttStore 解析 → deviceStore.applyMqttReport() → 模板响应式更新
MQTT 断连时降级为 5 秒 HTTP 轮询

### 人脸自动抓拍
useFaceCapture 的 watch 检测 humanDetected: 0→1 且 defenseStatus === 1
→ 打开摄像头抓帧 → POST /api/face/identify → 显示匹配结果

### 登录流程
LoginPage → authStore.login() → loginApi (POST /api/login)
→ 成功存 token 到 localStorage → 按角色跳转对应路由
→ 网络失败时提供离线模拟登录

## 网络层

- Axios 实例 baseURL: '/api'，Vite 代理到 http://192.168.20.42:8080
- 请求拦截器自动带 Bearer token
- 响应拦截器统一检查 code !== 200 并抛错，401 跳登录
- 文件上传用 FormData，Axios 自动设 multipart/form-data

## 路由结构

| 路径 | 布局 | 角色 |
|---|---|---|
| /resident | ResidentLayout | 居民 |
| /guard | GuardLayout | 保安 |
| /admin | AdminLayout | 管理员 |
| /login, /register | 无布局 | 公开 |
| /common/camera, /common/local-camera | 无布局 | 已登录 |
